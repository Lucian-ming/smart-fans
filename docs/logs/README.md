# 实验日志

按「一次实验一个文件」记录，文件名 `YYYY-MM-DD-主题.md`，例如 `2026-11-05-首板上电.md`。

## 为什么要写

- 失败往往比成功更有价值：记下**当时的现象、怀疑、验证手段**，一周后还看得懂。
- 硬件问题难复现，日志是唯一的现场证据。
- 复盘时能直接看到哪些改动引入了回归。

## 模板

```markdown
# YYYY-MM-DD 主题

## 目标
本次要验证/解决什么。

## 环境
- 硬件版本：revA / 板号 #1
- 固件版本：v0.1.0 / commit
- 仪器：万用表型号、示波器、电源型号
- 环境：室温、供电电压

## 过程
1. 做了什么，参数是什么
2. 观察到的现象（附数据/截图路径）

## 结果
✅ 通过 / ❌ 失败 / ⚠️ 部分通过

## 结论与下一步
- 根因（若已知/若仍是假设请标注）
- 下一步动作，谁负责
```

## 记录规范

- 现象只写事实：**"示波器测得 PWM 上升沿 1.2 µs，栅极有 8 V 过冲"**，而不是"驱动有问题"。
- 数字一定带单位；存疑的结论标注「假设」。
- 截图、波形图放 `docs/logs/assets/`，用相对路径引用。
- 同一问题跨多次实验，在最新一篇里链接前几篇，形成链条。
