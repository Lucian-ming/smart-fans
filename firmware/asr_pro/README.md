# ASR-PRO 离线语音驱动双 8x8 点阵眼睛表情系统指南

> **设计目标**：将原本由 STM32 驱动的 8x8 MAX7219 点阵模块功能解耦移交至 **ASR-PRO 离线语音开发板**。采用两块 8x8 点阵模块**串联（级联）**，左边一块显示左眼，右边一块显示右眼，实现拟人化动态萌宠表情交互。

---

## 1. 硬件接线示意图

两块 MAX7219 8x8 点阵模块按如下方式与 ASR-PRO 开发板连接：

```text
  +-------------------+       +-------------------+       +-------------------+
  |      ASR-PRO      |       |  点阵屏 1 (左眼)   |       |  点阵屏 2 (右眼)   |
  |    离线语音核心板  |       |   MAX7219 8x8     |       |   MAX7219 8x8     |
  |                   |       |                   |       |                   |
  |  5V  (P1-7)  ----+------>| VCC (必须5V)      |       |                   |
  |  GND (P1-8)  ----+------>| GND               |       |                   |
  |  PA0 (P2-5)  ----+------>| CLK (时钟)        |       |                   |
  |  PA5 (P1-2)  ----+------>| DIN (数据)        |       |                   |
  |  PA6 (P1-1)  ----+------>| CS  (片选)        |       |                   |
  |                   |       |      DOUT --------+------>| DIN               |
  |                   |       |      CLK ---------+------>| CLK               |
  |                   |       |      CS ----------+------>| CS                |
  |                   |       |      VCC ---------+------>| VCC               |
  |                   |       |      GND ---------+------>| GND               |
  +-------------------+       +-------------------+       +-------------------+
```

### 引脚对应表

| ASR-PRO 引脚 | 功能 | 连接目标 | 说明 |
| :--- | :--- | :--- | :--- |
| **5V / VIN**（P1 第 7 脚） | 5V 电源 | 点阵1 `VCC` | 取自开发板 5V 输出。**严禁接 3V3**——3V3 是芯片内部 LDO 输出，电流不超过 10mA，点阵必不亮 |
| **GND**（P1 第 8 脚，或 P2 第 7 脚） | 电源地 | 点阵1 `GND` | 必须共地，否则一定不亮 |
| **PA0**（P2 从上往下第 5 脚） | SPI CLK (时钟) | 点阵1 `CLK` | 串行时钟。**不能用 PA4**：PA4 是固件烧录使能脚 PG_EN，板载并联了红色 LED D4、3.3kΩ 上拉电阻和 CH340 DTR 三极管 Q2，上电高电平会让芯片进入编程模式 |
| **PA5**（P1 第 2 脚） | SPI MOSI (数据) | 点阵1 `DIN` | 串行数据输入 |
| **PA6**（P1 第 1 脚） | 片选 (CS / LOAD) | 点阵1 `CS` | 锁存信号，上升沿锁存 |

> **级联引脚连接**：
> - 点阵1 的 `DOUT` 接点阵2 的 `DIN`；
> - 点阵1 的 `CLK`、`CS`、`VCC`、`GND` 分别并联至点阵2 的对应引脚。

### ASR-PRO 开发板排针丝印对照（从上往下数）

> 数据来源：杭州天问五幺《ASRPRO 开发板规格书 V1.1》表 4 管脚定义表。**接线以板子排针旁的丝印为准**，序号只作辅助。

| P1（左侧） | 丝印 | 上电默认态 | 可复用功能 |
| :--: | :-- | :-- | :-- |
| 1 | PA6 | IN，下拉 | IIS0_MCLK / PDM_CLK / UART2_RX / PWM4 |
| 2 | PA5 | IN，下拉 | IIS0_SCLK / PDM_DAT / UART2_TX / PWM3 |
| 3 | PA3 | IN，下拉 | IIS0_LRCLK / IIC0_SCL / UART1_RX / PWM1（已作 Serial1 RX） |
| 4 | PA2 | IN，下拉 | IIS0_SDI / IIC0_SDA / UART1_TX / PWM0（已作 Serial1 TX） |
| 5 | PB6 | IN，上拉 | UART0_RX |
| 6 | PB5 | IN，上拉 | UART0_TX |
| 7 | **5V** | 电源 | **点阵 VCC 取这里** |
| 8 | **GND** | 电源 | 地信号 |

| P2（右侧） | 丝印 | 上电默认态 | 可复用功能 |
| :--: | :-- | :-- | :-- |
| 1 | SPK+ | — | 喇叭输出 |
| 2 | SPK- | — | 喇叭输出 |
| 3 | PC4 | IN，上拉 | IIC0_SCL / PWM0 / PDM_CLK |
| 4 | PA1 | 外部晶振 XOUT | GPIO PA1 |
| 5 | **PA0** | 外部晶振 XIN | **点阵 CLK 取这里**（GPIO PA0 / PWM5） |
| 6 | 3V3 | 电源 | 芯片内部 LDO 输出，**≤10mA，禁止给点阵供电** |
| 7 | GND | 电源 | 地信号（备用） |
| 8 | PA4 | IN，上拉 | GPIIO PA4 / **PG_EN 烧录使能（高电平进编程模式）** / IIS0_SDO / PWM2 |

### 点阵模块 5 个引脚怎么认

MAX7219 8x8 模块（FC-16 型）引脚都印在模块边上的丝印里，**按丝印接、不要按位置猜顺序**：

| 模块丝印 | 含义 | 接到 |
| :-- | :-- | :-- |
| `VCC` | 5V 电源 | ASR-PRO P1-7（5V） |
| `GND` | 地 | ASR-PRO P1-8（GND） |
| `DIN` | 串行数据输入 | ASR-PRO P1-2（PA5） |
| `CS`（有的印 `LOAD`） | 片选/锁存 | ASR-PRO P1-1（PA6） |
| `CLK` | 串行时钟 | ASR-PRO P2-5（PA0） |

> 级联方向：点阵1 的 `DOUT`（有的印 `DOUT`，在另一端）接点阵2 的 `DIN`；点阵2 的 `VCC/GND/CLK/CS` 与点阵1 同名脚并联。
> 两块点阵必须共用同一组 5V 和 GND，**不要从不同电源分别取电**。

## 2. 表情库与动画逻辑

代码内置了高对比度拟人化卡通眼睛表情库，由独立的 FreeRTOS 任务（50ms 刷新率）在后台平滑驱动：

| 表情名称 | 视觉特征 | 触发场景 |
| :--- | :--- | :--- |
| **常态大眼 + 自然眨眼** | 圆润大眼睛，带眼神高光；每约 **1.3 秒**眨眼一次（半闭 60ms → 全闭 180ms → 半睁 60ms），由 `blink_cnt >= 20` 计数器驱动 | 风扇正常运转或待机时的常态 |
| **欢喜笑眼 `^^`** | 两弯弯月牙笑眼 | 开机（“风扇风扇/打开风扇”）、送风、“好热啊” |
| **安睡闭眼 `--`** | 宁静祥和的单线闭合双眼 | 关机（“关闭风扇/我出门了”）、睡眠模式（“晚安/我要睡觉了”） |
| **俏皮眨单眼 `^_-`** | 左眼笑眯眯闭合 `^`，右眼睁大圆溜溜 `O` | 唤醒打招呼反馈（“风扇风扇”）、模式切换、音量调节 |
| **左右跟随张望** | 眼珠随摆头节奏每 2 秒左右转动张望 | 风扇开启摆头时（与 90° 舵机往复摆头节奏完美同步） |
| **惊讶圆眼 `OO`** | 睁大震撼的大空心圆眼 | 极速劲风（“快热死了/最高风速”）、高温超过 30°C |
| **爱心萌眼 `<3 <3`** | 两颗亮起的爱心双眼 | 用户表扬夸奖（“爱死你了/你好棒/喜欢你”） |
| **眩晕旋转眼 `@ @`** | 蚊香状同心方环 | 模式切换、高频调速 |

## 4. 常见方向与接线微调

在 `智能语音风扇.hd` 开头预留了便捷配置宏：

- **左右眼颠倒**：若发现左眼显示在右边屏幕上，将宏改为：
  ```cpp
  #define EYE_LEFT_IS_MODULE_1  0  /* 改为 0 即可左右调换 */
  ```
- **点阵上下倒置**：若模块安装方向上下反了，将宏改为：
  ```cpp
  #define EYE_ROTATE_180        1  /* 改为 1 即可一键上下倒置 180 度 */
  ```
- **时钟引脚（已定稿，不要改）**：`MATRIX_CLK_PIN` = **0（PA0，P2 排针从上往下第 5 脚）**。
  代码里已**彻底移除 PA4 的一切引用**——包括 `clk_low()/clk_high()` 里原先对 PA4 的双写、
  `max7219_pin_setup()` 里对 PA4 的 `set_pin_to_gpio_mode/pinMode`，以及 `dpmu_set_io_direction(PA4, ...)`。
  现在整份固件只驱动 PA0 这一根时钟线，PA4 保持空闲，不会再干扰 CH340 烧录。
  若将来必须换脚，只改 `MATRIX_CLK_PIN` 一个宏，编号按 wiring.h 体系：`0~7 = PA0~PA7`、`8~15 = PB0~PB7`、`16~23 = PC0~PC7`、`24+ = PD0~`。

  ```cpp
  #define MATRIX_CLK_PIN        0   /* 0 = PA0，当前实际接线 */
  ```

  > 已实测：把 PA0 和 PA4 **同时**当 CLK 双写也能点亮，但那会让 PA4（PG_EN）高频翻转，
  > 埋下"偶尔烧录失败/进编程模式"的雷，所以清理版已删除 PA4。

## 5. 踩坑与排障记录（2026-11 实测，改代码前必读）

这一段是从"烧录后点阵完全不亮"到"语音表情全通"的完整记录。下面每一条都是**真机验证过**的结论，不要凭直觉推翻。

### 5.1 硬件三坑

| 坑 | 现象 | 根因 | 正确做法 |
| :-- | :-- | :-- | :-- |
| **VCC 接 3V3** | 128 颗 LED 全黑 | P2 第 6 脚 3V3 是芯片内部 LDO 输出，**最大 10mA**；一块 8x8 MAX7219 全亮要几百 mA | 必须接 **P1 第 7 脚 5V** |
| **CLK 接 PA4** | 点阵花屏/不亮，烧录偶发失败 | PA4 = **PG_EN 烧录使能**，板载 D4 红 LED + 3.3kΩ 上拉 + CH340 DTR 三极管 Q2 并联，方波边沿被破坏，且高电平会进编程模式 | CLK 用 **PA0（P2-5）**，纯净 GPIO |
| **点阵1 的 DOUT 没接点阵2 的 DIN** | 只有一只眼睛亮 | 级联必须 点阵1 `DOUT` → 点阵2 `DIN`，其余四线并联 | 见第 1 节接线图 |

### 5.2 软件四坑

**坑 1：`userapp_initial()` 根本不执行 —— 这是"点阵完全不亮"的头号原因**

SDK 的 `projects/offline_asr_sample/src/system_msg_deal.c:841` 里，`userapp_initial();` 挂在
`case SYS_MSG_TYPE_AUDIO_IN_STARTED:` 分支内。这块板子上该分支从未走到，于是 SDK 内置的
`xTaskCreate(hardware_init, "hardware_init", 256, NULL, 100, NULL)` 永远不触发，`hardware_init()` 里创建的任务全部不存在。

**对策（已生效）**：把 `eye_animation_task` 和 `max7219` 初始化从 `hardware_init()` 里**挪进 `setup()`**。
调度器启动前后都能用的初始化路径必须只依赖忙等（`__asm__ volatile("nop")`），不能调 `delay()/vTaskDelay()`。

**坑 2：任务优先级抢死看门狗 → 无限"全亮→眨眼→全亮"复位循环**

SDK 的所有任务（`audio_in_manage_inner_task`、`UserTaskManageProcess`、`task_init`、`record_task`）优先级都是 **4**，
喂狗动作就在这些任务里（`audio_in_manage_inner.c:202`、`ci_task_monitor.c:151`）。IWDG 超时约 **2 秒**（`main.c:105-112`）。
把 `eye_animation_task` 提到 **5** 并且循环里纯忙等不让 CPU，喂狗任务就永远跑不到 →
IWDG 复位 → 重新 `setup()` 画全亮 → 又眨几眼 → 又复位。用户看到的"全亮眨眼一阵再全亮循环"就是这个。

**对策（已生效）**：任务优先级 **4**（与 SDK 同级，靠 `configUSE_TIME_SLICING 1` 时间片轮转），
循环末尾用 `delay(50)`（= `vTaskDelay(25)`，tick 2ms）**主动让出 CPU**。

**坑 3：串口日志完全读不到 —— 不要靠串口做观测**

`user_config.h:66` 的 `CONFIG_CI_LOG_UART 0` 本来就关了日志串口；`Serial`(UART0 = PB5/PB6) 的 TX 也没有回到 CH340 的 RX。
实测以 115200/9600/921600、DTR/RTS 四种组合去读 CH340，**始终 0 字节**。
`setup()` 里的 `Serial.println("ASR_PRO_ONLINE")`、每一帧的调试输出，全都是发给虚空。
**观测手段只剩：看屏幕/点阵本身**。

**坑 4：`millis()` 曾一度被怀疑失效（最终是误诊，但教训有效）**

`wiring.c:382-387` 的 `millis()` 读 `TIMER_MTIME` 再 `/18320`。当时"圆眼不动"被归因为 `millis()` 恒定，
于是加过任务本地软时钟 `g_soft_ms`。**真正原因其实是眨眼门槛太高（40 轮 × 50ms）加上任务被音频任务挤占**。
`g_soft_ms` 现在仍保留（表情超时恢复用它），但它不是必需品——`vTaskDelay` 与 `delay()` 都是好的。

### 5.3 调参过程中最有用的一次判定实验

把 NORMAL 分支改成"奇数轮画瞳孔偏左、偶数轮画圆眼"，让画面产生肉眼可见的抖动：
- 眼睛**抖了** → 说明 `while(1)` 在正常循环，问题在眨眼判据；
- 眼睛**不抖** → 说明任务根本没在循环。

用户回了一个"抖"字，就此锁定"循环正常、只是门槛太高"，省掉了后面所有瞎猜。

### 5.4 构建与烧录的可靠观察方式

在 `D:\天问Block\asrpro\asr_pro_sdk\projects\offline_asr_sample\project_file` 下执行：

```bash
cmd.exe /c build.bat 2>&1 | tr '\r' '\n' | tail -20
```

- **必须**用 `tr '\r' '\n' | tail` 看尾部，**不要用 grep 匹配中文**（GBK 输出，编码不匹配会漏掉关键行，导致误判"烧录失败"）。
- 真烧进去的标志是连续出现：`开始校验:0,1cb000` → `校验 0 ok` → `目标程序数据校验 0 ok` → `复位设备` → `复位设备成功` → `烧录完成`。

- 若 `makebin` 长时间无输出，先确认 CH340 还在：
  `python -c "from serial.tools import list_ports; [print(p.device,p.description) for p in list_ports.comports()]"`。
  重插 USB 后 **COM 号可能变化**（实测 COM14 → COM15 → COM14），`makebin` 会自动枚举，无需改配置。
- `asr.cpp` 与 `智能语音风扇.hd` 是**两份必须同步维护**的源码，`.hd` 末尾多一行 `/** edittype="asr_procode" */`。
