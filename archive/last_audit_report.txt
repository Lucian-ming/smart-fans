## 二、物理空间与零碰撞

### 2.1 尺寸与板框 ✅
Edge.Cuts 由 8 段构成 3mm 倒角八边形，bbox `X[100,198] Y[100,198]` → **98.0×98.0mm**，嘉立创免费券（≤100×100、2 层）合规。但注意：机械文档 `docs/mechanical/casing-design.md:56` 写的是"**85.0×85.0mm（倒圆角 R=3.0）**"，且底座内腔仅 **90×90** —— 98×98 的板**根本放不进去**。板框形状也从"R3 圆角矩形"变成了"3mm 倒角八边形"。

### 2.2 安装孔禁布区 ✅（数据见下）
| 孔 | 中心 | 最近焊盘 | 焊盘中心距 | 边到孔心净距 |
|---|---|---|---|---|
| H1 | (5,5) | DC1.3 | 7.58 | **6.93mm** |
| H2 | (93,5) | SERVO1.3 | 6.07 | **5.43mm** |
| H3 | (5,93) | J_KEY1.1 | 10.52 | **9.87mm** |
| H4 | (93,93) | J_OLED.4 | 22.30 | **21.65mm** |

均 >4.5mm，无走线侵入（最近 10.78mm）。**但**角部 3mm 斜边使 φ6.0 孔盘到板边仅剩 **1.95mm**，铣边公差 ±0.1mm 下建议加大到 2.2mm 以上或改为 R3 圆角。

### 2.3 模块碰撞 ❌ —— 这是"零碰撞"声明的破点

我先把 PNG 里的色块按实色填充做了精确测量（px/mm=23.133）：

| 模块 | 图绘包络 (mm) | 实测尺寸 | 标称尺寸 | 差异 |

| ASR-PRO | x64.93–94.97 / y26.02–54.04 | 30.0×28.0 | 30×28 | ✅ |
| OLED | x65.92–93.98 / y58.45–85.46 | 28.1×27.0 | 27×27 | ≈ |
| TB6612 | x7.09–29.09 / y28.19–47.90 | 22.0×19.7 | 21.5×19 | ≈ |
| PAJ7620 | x13.79–34.37 / y64.19–79.58 | 20.6×15.4 | 20×15 | ✅ |

**问题定性**：作"零碰撞"证明时，按键包络被缩到 11.9mm（实际 19.6mm）、编码器缩到 22mm（实际 26mm）。按标称尺寸、以插座中心对称放置重算：

- PAJ 底边 **79.5** vs 按键顶边 **78.2** → **纵向重叠 1.3mm**（间距 = −1.3mm）
- 按键2 右边 **40.75** vs 编码器左边 **40.0** → **横向重叠 0.75mm**
- 编码器右边 **66.0** vs OLED 左边 **65.92** → **重叠 0.08mm**
- 按键真实包络到底板边 **97.8 vs 98.0**，只剩 **0.33mm**

而且这是**最宽容的假设**：按键/编码器的 3P/5P 插座在模块的一条边上，不是几何中心。若插座在模块后缘，按键体将伸到 y≈107.6，**出板 9.6mm**；若在前缘，则压进蓝板（y≤73）与 PAJ。**两种装法都不成立。**

按图绘包络也仍有 1 处违规：**按键2 ↔ 编码器 0.91mm < 1.5mm**。

## 三、电气原理与驱动链路

### 3.1 电源链路 ❌ —— 三个致命缺陷叠加

**（1）XL1509 反馈脚悬空（P0）**
```
net 6 "XL1509_FB"：1 个焊盘（U2.3），0 段走线
```
XL1509-5.0 是固定 5V 版本，FB 必须直连 VOUT。悬空后误差放大器输入不确定，占空比极易跑到最大 → 输出趋向 12V 直通，一次性烧掉 AMS1117、ASR-PRO、TB6612 VM、舵机、蜂鸣器。**这是整板第一优先级缺陷。**

**（2）GND 被写成 net 0（P0）**
文件头 `(net 0 "GND")`，38 个焊盘标 `(net 0 "GND")`。KiCad 中 **net 0 是保留的"无网络"**，所有 GND 焊盘在网表中等于悬空；全板 **0 个 zone、0 段 GND 走线**。也就是说这块板**没有任何地回路**：降压没有回流路径、去耦电容不起作用、TB6612 的 GND 与 MCU 的 GND 不连通。

**（3）整板几乎未布线（P0）**
- 154 个焊盘、28 个网络，只有 **10 段走线、0 个过孔、0 个铜皮**
- **23 个"有 ≥2 个焊盘"的网络铜箔数 = 0**（I2C、编码器 A/B、蜂鸣器、LED、OLED、按键、TB6612 控制、语音串口全部悬空）
- 已布的只有：`+12V_RAW`(1)、`+12V_IN`(2)、`+5V`(3)、`+3.3V`(1)、`XL1509_SW`(1)、`TB_AO1`(1)、`TB_AO2`(1)

**（4）Gerber 是空壳（P0）**
`hardware/fabrication/gerber_revB/fan_ctrl_revB.GTL` 全文仅 3 行：
```
G04 Top Copper Layer for Smart Fan Controller RevB (JLCPCB 2-Layer)*
G04 Board Size: 98.0mm x 98.0mm*
M02*
```
无光圈定义、无坐标、无 D 码、无曝光——**打出来是一块纯空白基板**。DRL 同理。这个包不能投板。

**（5）无原理图可作为依据**
`hardware/kicad/` 下只有 `fan_ctrl_revA.kicad_sch`，且是 501 字节的空壳（`(lib_symbols)` 为空，0 个元件），**revB 完全没有原理图**。PCB 是脚本生成的孤岛，无网表来源、无法做原理图-PCB 比对。

### 3.2 供电能力 ❌

| 负载 | 典型 | 峰值/堵转 |
|---|---|---|
| STM32 蓝板 | 50mA | 80mA |
| ASR-PRO（含喇叭） | 150mA | 450mA |
| 0.96″ OLED | 20mA | 25mA |
| PAJ7620 | 10mA | 15mA |
| DHT11 | 0.5mA | 1mA |
| MG90S 360° | 100mA | **700mA（堵转）** |
| 130 电机（经 TB6612） | 150mA | **1200–1500mA（堵转）** |
| 蜂鸣器 + LED×2 | 34mA | 34mA |
| **5V 侧合计** | **≈515mA** | **≈2.8A** |

- **静态够、动态不够**：`2.8A > XL1509 的 2A 限流`。电机启动+舵机同时动作+语音播报必然拉垮 5V → MCU 欠压复位。
- **热设计不成立**：12V→5V @1.5A 耗散 ≈1.3W，SOIC-8 的 θJA≈80°C/W，ΔT≈100°C；而板上**没有铜皮**（0 zone），等于无散热面积 → 必然热关断。
- **3.3V 侧没问题**：AMS1117 负载约 81mA，耗散 0.14W，余量充足。
- **TB6612 VM 无就近储能**：220µF/16V 的 C3 在 U3 旁（x=62），距 TB6612 母座（x=18）约 44mm，中间只靠一段 0.8mm 的 B.Cu 长线 → 电机 PWM 纹波直接打到 MCU 的 5V 上。
- 无保险丝、无 TVS、无输入过压保护。

### 3.3 TB6612 与 TIM2 ❌

按标准蓝板右排定义（自 USB 端起 `VBAT,PC13,PC14,PC15,PA0…PA7,PB0,PB1,PB10,PB11,RST,3V3,GND,5V`）换算：

| 信号 | PCB 焊盘 | 实际 MCU 脚 | 固件期望 | 冲突 |
|---|---|---|---|---|
| TB_PWMA | J_MCU_R.12 | **PA7 = TIM3_CH2** | 风扇 PWM = **PA0/TIM2_CH1** | ❌ 不是 TIM2；且 PA7 被固件用作编码器 B |
| TB_AIN1 | J_MCU_R.11 | PA6 | 编码器 A = PA6 | ❌ |
| TB_AIN2 | J_MCU_R.8 | **PA3** | ASR-PRO RX（USART2） | ❌ 直接抢语音口 |
| TB_STBY | J_MCU_R.7 | **PA2** | ASR-PRO TX（USART2） | ❌ 直接抢语音口 |
| SERVO_PWM | J_MCU_R.6 | PA1 | PB8/TIM4_CH3 | ❌ |
| ENC A/B/SW | J_MCU_R.4/3/2 | **PC15/PC14/PC13** | PA6/PA7/PB12 | ❌ 非定时器脚，且 PC14/15 是 32.768k 晶振脚 |
| VOICE TX/RX | J_MCU_R.10/9 | PA5/PA4 | PA2/PA3 | ❌ |
| GEST_INT | J_MCU_L.16 | PB5 | PA4 | ❌ |

**"与 TIM2 零冲突"的表面成立，实际是"根本没接到 TIM2"**；而 TIM2 的 PA0–PA3 恰好被 STBY/AIN2 占掉两个，正好是语音模块要用的 USART2。

**更致命的是插接短路（P0）**——无论正插反插都短：

- **正插（0°）**：蓝板右排第 20 脚是 **5V**，PCB 该位置是 **GND** → **5V 直接短地**；同时左排第 3 脚 5V 落到 `BUZZER_CTRL` → 5V 灌进 GPIO。
- **反插（180°）**：蓝板左排第 3 脚 5V 落到 PCB 右排第 18 脚 = **+3.3V** → **5V 与 3.3V 电源短路**。

也就是说，这块板**只要把蓝板插上去就冒烟**。根因是两排母座的引脚编号方向不一致（左排把 +5V/GND/+3V3 放在 18/19/20，右排也放在 18/19/20），而实物模块的两排是**镜像**的。

### 3.4 传感器与交互 ❌
- **I2C 无上拉**：BOM 里只有 R_DHT(4.7k) 给 DHT11，R1/R2/R10 是 LED 与蜂鸣器用。OLED 与 PAJ7620 若模块板载上拉则可用，否则 I2C 直接不通。**设计上必须显式加 2×4.7k。**
- **PAJ7620 与 OLED 共用 I2C1**（PB6/PB7）✅ 地址不冲突，合理。
- **DHT11** 单总线 + 4.7k 上拉 ✅ 电路正确，但固件 `pins.h` 写的是 PA1/DS18B20，且 BOM 无 DS18B20 → 软硬件不是同一产品。
- **编码器接 PC13/14/15** 不合理：无定时器输入、需软件轮询、抗抖动差，且 PC14/15 与 LSE 晶振复用。
- **两个大按键**接 KEY1_SIG/KEY2_SIG，但固件定义了 BTN_MODE(PB13)/BTN_SWING(PB15)/BTN_AUX(PB0) 三个按键 —— 数量都不一致。
- 蜂鸣器驱动链路（R10 1k → Q1 2N3904 → BZ1 + D3 续流）拓扑正确 ✅，但 **Q1 三个焊盘互相重叠**（见 3.5），基极-发射极-集电极全短，蜂鸣器会常响。

### 3.5 DRC：8 处焊盘物理重叠 ❌
| 器件 | 重叠对 | 间隙 |
|---|---|---|
| Q1 (TO-92) | 1–2 | **−0.53mm** |
| Q1 | 2–3 | **−0.53mm** |
| U2 (SOIC-8) | 1–2 | −0.13mm |
| U2 | 2–3 | −0.14mm |
| U2 | 3–4 | −0.13mm |
| U2 | 5–6 | −0.13mm |
| U2 | 6–7 | −0.14mm |
| U2 | 7–8 | −0.13mm |

根因是**全板 35 个器件共用一个自造的 `Module:Socket` 封装**，焊盘一律 1.8×1.8（直插）或 1.2×1.4（贴片），完全不看实际 pitch：
- TO-92 引脚间距 1.27mm，却用 1.8mm 圆盘 → 三脚连成一片；
- SOIC-8 间距 1.27mm，却用 1.4mm 高的盘 → 相邻脚互连；
- 0805 用 1.2×1.4 盘、±0.9mm 间距，勉强能焊但不是标准焊盘。

这是**物理短路**，不是"警告"。

## 四、BOM 与立创器件化

**形式合规 ✅**：23 行全部有 C 编号，位号合计 35 个，与 PCB 非孔件一一对应；抽验 C61063=XL1509-5.0E1、C16214=DC-005 2.0、C106552=100µF/25V 均真实有效。

**实质问题 ❌**：
1. **J_VOICE_L/R 数量不符**：BOM 写 `2.54-1*8P母`，PCB 实际只有 **7 个焊盘** → 8P 排母插不进 7 孔位。
2. **MPN 列是中文描述**（"16V220uF CD288"、"2.54-1*8P母"），不是厂家料号。一旦 C 编号有误，嘉立创的 MPN 兜底匹配会失败。
3. **三套 BOM 互相矛盾**：`docs/hardware/bom.md` 写 XL1509=C2681227、DS18B20=C7817、绿灯=C2290、4.7k=C25900，与 xlsx 全部不同；`bom.md` 里还有 FAN1/FAN2/SPK1/MIC1/AO3400A/3 个 6×6 轻触——那是 4 线风扇方案的物料。**到底以哪套下单？**
4. **3D 模型：0 个**。全文 `grep "(model"` 计数为 0。嘉立创 EDA 专业版导入后，**35 个器件全部没有 3D 体**，"正确载入 3D 视觉模型"不成立。
5. **导入会失败或降级**：
   - 35 件全用 `Module:Socket`，KiCad 官方库无此封装，EDA 解析不到 → 全部退化为裸焊盘；
   - 文件头 `version 20221018`（KiCad 7）却用了 KiCad 8 的 `(property "LCSC" …)` 语法 → 严格解析器会直接报错；
   - `(net 0 "GND")` 非法 → 导入后 GND 变成无网络，DRC 会报几百条未连接。

`hardware/easyeda/README.md` 整篇还在讲 **85×85、4-Pin 风扇、KF2510、3 个轻触**，且指向 `references/01_bishe_voice_fan/…epro2`——与 revB 无关，属过期文档。

| 手势窗 | φ8.0 + 45°×1.0 倒角 | PAJ 在 (24,72) | ⚠️ 坐标随板变，需重排 |
| 旋钮 | φ7.5 | 编码器在 (53,87) | ⚠️ 同上 |

### 5.2 25° 倾斜的几何验算（即使孔位对上也不成立）

- **按键**：按键轴线垂直板面，面板倾斜 25°，φ4.0 孔在 2mm 面板上的有效投影 = `4.0 − 2×2×tan25° = 4.0 − 1.87 = 2.13mm`。标准 6×6 按键帽直径 3.5mm → **过不去，会卡死**。要么孔放大到 φ6.5 以上，要么做沉孔/球面倒角。
- **旋钮**：φ6 轴穿 φ7.5 孔，2mm 面板倾斜 25° 产生的横向偏移 = `2×tan25° = 0.93mm`，单边余量只有 `(7.5−6)/2 = 0.75mm` → **轴会刮孔壁、手感发涩**。建议 φ9.0 或加轴套。
- **OLED 视口**：24×14 有效区倾斜 25° 后投影高 = `14×cos25° = 12.7mm`；若面板与屏面间隙 3mm，还需加 `2×3×tan25° = 2.8mm` → 需要 **15.5mm**，而外壳只给了 **15.0mm** → **视口偏小，上下边缘会被切掉**。
- **PAJ 视场**：45° 倒角本身合理，但面板倾斜 25° 后锥体一侧被面板内壁切掉，实际可用半角从 45° 降到约 32°，手势识别距离会明显缩短。
